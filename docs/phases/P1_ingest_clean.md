# P1 — Ingest and clean

**Goal:** one typed, cleaned ticket table plus a reproducible Day-0 report. **Time box:** 1.25 h.
**Lane:** A. **Agents:** `line-cook` builds, `sous-chef` reviews. **Depends on:** P0 (venv, scaffold).

The stdlib pre-check (23 Nov) already confirmed CLAUDE.md facts 1–3 on the full file, so this phase codifies them reproducibly and fast. The pre-check took 3 min 23 s in pure Python; DuckDB should take seconds.

## Inputs
`data/raw/tickets/October-Delhi.csv`: comma-separated, quoted strings, literal `NULL`, `is_ac` = `True`/`False`, every timestamp `+05:30`.

## Outputs
- `scripts/day0.sql` and `docs/DAY0.md` (generated by `python -m seatcast.run day0`).
- `data/work/tickets.parquet` (`io.py`, `clean.py`).
- `tests/test_parse.py`, `tests/test_norm.py`.

## Steps

1. **`scripts/day0.sql`**: CLAUDE.md §3 with the fixes.
   ```sql
   CREATE OR REPLACE TABLE x AS
   SELECT CAST(passenger_count AS INT) pc, CAST(amount AS DOUBLE) amt, vehicle_number v,
          ticket_type_id tt, start_stop_name ss, end_stop_name es, route r,
          CAST(regexp_replace(created_at, '\+05:30$', '') AS TIMESTAMP) ts,   -- all rows are +05:30 (assert below)
          lower(is_ac) = 'true' ac
   FROM read_csv('data/raw/tickets/October-Delhi.csv', header = true, nullstr = ['NULL', ''], all_varchar = true);
   SELECT COUNT(*) FILTER (WHERE NOT created_at LIKE '%+05:30') bad_tz FROM read_csv(...);   -- expect 0
   ```
   - Report shares **by passengers and by rows**.
   - Keep the existing queries (counts, fare slabs, ticket types, vehicle coverage, per vehicle-day quantiles, daily totals, weekday hourly profile).
   - **Add:**
     - Saturday and Sunday hourly profiles.
     - `passenger_count` distribution.
     - Series × `is_ac` passengers and distinct vehicles.
     - **Series × route prefix**, e.g. `r LIKE 'D-%'`, to test whether `D-` routes are DEVi and which series runs them (THINKING D-07).
     - Top 20 route codes.
   - `run.py day0` executes the SQL and writes each result as a markdown table into `docs/DAY0.md`. No hand-typed numbers.

2. **`clean.py`**
   - `parse_route`: CLAUDE.md §4.2, with the ring base widened to `[A-Z0-9-]+?` so `D-5509(-)` parses.
     - The 9 named services (e.g. `DS CIRCULAR`, `AIIMS BADSA TO NAJAFGARH TERMINAL`, 877 passengers) return `None` and are listed in coverage.
     - Not worth hand-mapping 0.03%. `# ponytail: add to route_map.csv only if a demo route needs them.`
   - `norm`: run `html.unescape` first, then lowercase. Split letter–digit joins (`sec21` → `sec 21`), then apply `ABBR`. Extend `ABBR` with `bdr→border`, `pkt→pocket`, `apt|aptt|apts→apartment`, `rd→road`, `nr→near`, `hosp→hospital`, `jn→junction`, `ph→phase`. Both sides (tickets and GTFS) go through the same function, so extra rules are safe.
   - `fare_class(fare_pp, ac)`: `std` (90% slab) / `ncr` (22 + 4.5k) / `full` (undiscounted slab) / `other`.
   - `daytype(date)`: holidays in `config.holidays` → `sunday`; Saturday → `saturday`; Sunday → `sunday`; else `weekday`.
   - `anomalies(daily)`: deviation from the median of the same day type and weekday, **after** holiday reassignment. Flag |dev| > 30%. Expect none beyond the two holidays; 19 Oct (−19%) stays.

3. **`io.py`**: `load_tickets()` writes `data/work/tickets.parquet` with:
   `tid, pc, fare_pp, fare_class, ac, v, series, route_raw, base, dir, var, ss, es, ss_n, es_n, ts, date, dow, slot (0–47), daytype, week, f_pc_out (pc>3), f_zero, f_same_od`.
   - `v` and `series` are internal. They never reach `data/out/` or the API.
   - Do the heavy work in DuckDB SQL. Apply the Python `parse_route` and `norm` to **distinct** values only (2,259 codes, ~7,552 names) and join back.

4. **Tests**
   - `test_parse.py`: the six CLAUDE.md examples, `D-5509(-)` → `('D-5509','CCW','')`, `DS CIRCULAR` → `None`.
   - `test_norm.py`:
     - `Sabha Pur X-Ing` → `sabha pur crossing`
     - `Rohini Sec21` → `rohini sector 21`
     - `Old Delhi Railway Station (T)` → `old delhi railway station terminal`
     - `Kalindi Kunj Bdr` → `kalindi kunj border`
     - `Rohini Sec 24 / Dear Satguru Sewaram Crossing&#34;` → `rohini sector 24 dear satguru sewaram crossing`
     - `norm('Ito-Agcr') == norm('Ito Agcr')`

## Done when
- `docs/DAY0.md` regenerates and matches the pre-check:

  | Check | Expected |

  | per vehicle-day q50 / q90 / q99 / max | 6 / 16 / 35 / 89 |

- ≥ 99.9% of passengers have a parsed route.
- `pytest -q` is green.
- **Gate G1:** if any of facts 1–3 flips (non-discounted or zero-fare rows become material), stop and ask (CLAUDE.md §13).

## Gotchas
- `nullstr` must list both `'NULL'` and `''`.
- Never compare `is_ac` to `'TRUE'`.
- `fare_pp` = `amount / passenger_count`, rounded to 2 dp before slab tests (floating point).
- Weeks: 1–4 Oct sit outside the four ISO-style weeks in config; that's fine for ρ.
